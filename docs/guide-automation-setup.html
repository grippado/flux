setup guide

Wire GitHub, Linear, and Anthropic for an unattended issue pipeline.

This guide sets up the credentials for a GitHub Action that runs flux:refine and flux:issue on a GitHub issue and lands it in Linear, with a human approval step that never blocks a live terminal.

Overview

Three separate credentials cross three separate systems. None of them is your personal login: a runner in GitHub Actions never has your terminal's gh auth session or your local ~/.secrets, so each one is provisioned once, as a repository secret, scoped to this automation only.

Reference: this guide backs grippado/flux#62, the issue that specifies the pipeline itself.

GitHub access

A workflow triggered by issues: opened already receives a scoped, short-lived token as GITHUB_TOKEN. That token can read the issue and post the draft/result as a comment, no extra secret needed, as long as the workflow's permissions block grants it:

permissions:
  issues: write
  contents: read

A personal access token is only needed if the automation must reach past this repository (opening a PR in another repo, for example). Skip it unless that becomes true.

Linear API key

  1. Open linear.app/settings/account/security → Personal API keys → Create key.
  2. Label it so it is identifiable later, for example flux-issue-automation. A label tied to the purpose, not your name, makes it obvious what to revoke if this workflow is ever retired.
  3. Copy the value once. Linear will not show it again.
  4. In the flux repository: Settings → Secrets and variables → Actions → New repository secret. Name it LINEAR_API_KEY and paste the value.

Do not reuse your personal key. A workspace-scoped key on your own machine (LINEAR_API_KEY_PERSONAL, or whatever linear_token_env your local flux manifest declares) is a different credential store than a repository secret. One key per store is what lets you revoke the automation's access without touching your own.

Anthropic key

The runner needs its own way to invoke Claude, separate from your Claude Code subscription. Two options:

  • API key (console.anthropic.com → Settings → API Keys → Create Key): usage is billed as API consumption, metered per token. This is the simplest path for a workflow nobody watches.
  • Claude Code OAuth token, when the official claude-code-action is used: generated from an authenticated Claude Code session and stored the same way. Check the action's own docs for the exact command, since this changes with the action's version.

Either way, store the value as a repository secret, for example ANTHROPIC_API_KEY, next to LINEAR_API_KEY.

Wiring the secrets

In the workflow file, secrets are referenced, never inlined:

env:
  ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
  LINEAR_API_KEY:    ${{ secrets.LINEAR_API_KEY }}

GITHUB_TOKEN does not need this line: Actions injects it automatically for every job.

The async gate

The credentials above make the pipeline able to reach every system it needs. They do not decide when it is allowed to write to Linear. That is a separate, mandatory step: flux:issue never creates a tracker issue without approval, and an unattended run replaces the interactive terminal prompt with an async one, for example a comment posted back on the GitHub issue, gated on a second signal (a reply, a label, a reaction) before the run continues. The mechanics of that gate are specified in issue #62, not in this guide: this page only covers getting the three systems reachable.

Security notes

  • Never print a secret's value in a log, a comment, or a commit. If a workflow step needs to confirm a key resolved, log its presence (length, or a masked prefix), never the value.
  • Scope the Linear key to the workspace this automation targets. A key with access to every workspace you belong to is a wider blast radius than this automation needs.
  • Rotate a key immediately if a workflow run, a log, or a fork of this repository ever exposes it, even partially.
